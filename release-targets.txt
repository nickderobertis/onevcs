# The release targets of this repository: what a consumer can wait on, and the
# only identifiers scripts/release-probe.sh will answer for.
#
# One registry-qualified identifier per line, `<registry>:<name>`, where <name>
# is exactly the name that registry serves. Blank lines and lines opening with
# `#` are comments; nothing else on a line is.
#
# **The qualification is load-bearing rather than decorative.** `onevcs-cli` is
# both a PyPI project and an npm package, published from this one repository on
# two cadences, so an unqualified `onevcs-cli` names two different artifacts and
# a consumer waiting on it cannot say which one it got.
#
# A target is a **consumable** artifact — one a dependent names in order to
# depend on it. The five per-platform npm packages
# (`onevcs-cli-<platform>-<arch>`) are not targets of their own: they exist only
# so the `onevcs-cli` launcher can resolve one at its own exact version, they are
# named by nobody else, and `npm:onevcs-cli` is the wait that covers them.
#
# What this list deliberately does not name is the GitHub Release archive. It is
# a direct download rather than a registry artifact — there is no registry that
# serves it and so no identifier of this form for it — and what it ships is
# already held to this repository by
# `every_file_a_release_archive_names_is_in_this_repository` in
# crates/onevcs/tests/contract.rs.
#
# `the_declared_release_targets_are_exactly_what_this_repository_publishes`, in
# that same suite, reconciles this file with the *real* release configuration —
# .github/workflows/release.yml, pyproject.toml, and npm/onevcs/package.json — in
# both directions, so a name this repository starts publishing fails the gate
# rather than going undeclared, and a target declared here for something it does
# not publish fails it too.

crate:onevcs
crate:onevcs-testing
pypi:onevcs-cli
npm:onevcs-cli
